코드를 플래시(Flash)가 아닌 ITCM(Instruction Tightly-Coupled Memory) 영역에 적재하면, 캐시를 거치지 않고 프로세서 속도로 결정적(deterministic)으로 실행합니다.

이번 가이드에서는 Cortex-M55/M85(예: Nuvoton M55M1 시리즈) 코어 환경에서 ITCM에 코드를 적재해 실행할 때 점검할 항목을 정리합니다.

---

▷ 1. 배경: 런타임 코드 재배치(Relocation)

펌웨어 시동 코드(Reset_Handler)는 C 라이브러리 진입점(Arm Compiler는 __main, GCC는 __cmsis_start)을 호출하고, 이 코드가 플래시에 저장되어 있던 함수 바이너리를 ITCM 영역(SRAM 물리 메모리 맵 상의 다른 대역)으로 복사합니다.

---

▷ 2. FAE 조치 가이드

#### 1) 링커 스크립트 내 로드-실행 주소의 분리 (Scatter Loading)

Keil MDK의 스캐터 파일(.sct) 또는 GCC 링커 스크립트(.ld)에서 ITCM 적재 코드가 로드 주소(Load Address)와 실행 주소(Execution Address)를 식별하도록 구조화해야 합니다.

`text

// Keil Scatter File 예시

LR_ROM 0x00100000 0x00200000 { ; 로드 주소 (Flash 영역)

ER_ROM 0x00100000 0x00100000 {

*.o (RESET, +First)

*(InRoot$$Sections)

startup_M55M1.o

}

ITCM_EXEC 0x00000000 0x00010000 { ; 실행 주소 (ITCM 대역)

motor_control.o (+RO) ; ITCM 실행 대상 모듈

}

}

`

#### 2) I-Cache / D-Cache 동기화 처리 (Cache Coherency)

M55M1의 Cortex-M55는 L1 캐시에 대한 하드웨어 일관성(coherency)을 제공하지 않으며, BSP는 기본으로 명령어 캐시(I-Cache)와 데이터 캐시(D-Cache)를 모두 켭니다.

실행 코드를 런타임에 SRAM으로 적재했다면, 그 주소의 코드를 실행하기 전에 I-Cache를 무효화해 이전에 캐시된 명령어를 버리도록 초기화 코드를 구축합니다.

`c

// CMSIS 캐시 유지 관리 API 활용

SCB_CleanDCache();

SCB_InvalidateICache();

__DSB(); // Data Synchronization Barrier

__ISB(); // Instruction Synchronization Barrier

`

#### 3) 디버거 초기화 스크립트(Debugger Initialization Script) 연동

Keil의 디버깅 탭 옵션에서 Initialization File (*.ini) 스크립트를 연결하여, 디버깅 실행 시 스택 포인터(SP)와 프로그램 카운터(PC) 값을 설정해 주는 스크립트를 로드해 줍니다.

`text

// Keil MDK debug.ini 예시

FUNC void Setup (void) {

SP = _RDWORD(0x00100000); // 스택 포인터 로드

PC = _RDWORD(0x00100004); // 엔트리 주소 로드

}

Setup();

`
