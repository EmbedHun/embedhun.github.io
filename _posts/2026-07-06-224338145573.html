1. 개요 및 배경

누보톤 M480 및 최신 Cortex-M7/M55 아키텍처를 내장한 마이크로컨트롤러(MCU)들은 매우 빠르고 지연 없는 최속 연산(Zero-wait state) 성능을 구현하기 위해 ITCM(Instruction Tightly Coupled Memory) 영역을 하드웨어적으로 할당하여 제공합니다. ITCM은 CPU 클럭과 동일한 속도로 직접 구동되는 밀 결합 명령어 메모리입니다.

개발 시 인터럽트 서비스 루틴(ISR)이나 핵심 수학적 계산 알고리즘 루틴을 플래시 메모리가 아닌 ITCM에 적재하여 구동하면, 플래시 메모리 캐시 미스로 인한 실시간 지연 오차를 완전히 차단할 수 있습니다.

하지만 컴파일 단계에서 특정 함수의 로드 주소(Flash 영역)와 가상 실행 주소(ITCM 영역)가 이원화되는 구조로 인해, 디버거(Keil MDK 또는 GCC GDB)로 실행 상태를 디버깅할 때 중대한 기술적 장애를 겪게 됩니다. 디버깅 프로그램이 ITCM 영역에서 실행 중인 칩의 물리 레지스터 값을 원래 작성한 C 언어 소스 파일과 결합시키지 못해, 화면에 소스코드는 사라지고 엉뚱한 Disassembly(어셈블리 기계어 코드) 라인만 요동치는 소스 어소시에이션 에러(Source Association Error)가 발생합니다.

이 가이드북은 누보톤 고성능 코어 아키텍처 상에서 ITCM 영역에 동작 제어 코드를 할당하는 정석적인 링커 파일 구성법과 디버거 디버그 심볼 유실을 막아 정상 디버깅을 유지하는 실무 조치법을 상세 제시합니다.

2. 문제 발생의 본질적 이유 (로드 주소와 실행 주소의 괴리)

컴파일 시 ITCM 함수는 플래시 메모리(예: 0x00000000 대역)에 로드(Load)용 바이너리로 영구 보관된 후, MCU 시스템 부팅 단계(Reset Handler)에서 SRAM 내의 ITCM 실행용 가상 주소 대역으로 펌웨어 링커 카피 동작을 통해 물리 복제되어 기동합니다.

그 결과 실행 시점에 CPU의 프로그램 카운터(PC) 레지스터는 ITCM 주소 대역의 0번지 주소를 가리키고 동작하게 됩니다. 하지만 디버거는 컴파일 시 빌드된 디버그 정보(ELF/AXF 파일의 심볼 데이터)가 가리키는 원본 플래시 주소 영역만 추적하려고 시도하므로, 현재 실행 중인 프로그램 카운터 주소(ITCM)에 매칭되는 소스 코드 위치를 찾지 못하고 소스 코드 연동 화면을 강제로 유실시켜 버립니다.

3. 링커 분산 파일(Linker Scatter File / .ld) 포지셔닝 설계

Keil ARMCLANG 컴파일러 환경에서 특정 필수 지연 함수(Delay_Loop)를 ITCM 영역으로 할당하기 위한 정석적인 링커 파일(.sct) 기술 구조입니다.

[Keil Scatter File (.sct) 구조]

LR_IROM1 0x00000000 0x00080000  // 플래시 로드 영역 정의
{
    ER_IROM1 0x00000000 0x00080000
    {
        *.o (RESET, +First)
        *(InRoot$$Sections)
        .ANY (+RO)
    }
    // ITCM 실행 영역 매핑 정의
    // 로드 주소는 Flash 내에 존재하나 실행 주소는 ITCM 물리 영역(0x00000000 대역 등)으로 맵핑
    ER_ITCM 0x00000000 0x00010000
    {
        * (ITCM_SECTION) // ITCM 영역 지정을 위한 섹션 명시
    }
    RW_IRAM1 0x20000000 0x00020000
    {
        .ANY (+RW +ZI)
    }
}

[C 소스코드 내 함수 섹션 속성 지정 선언]

__attribute__((section("ITCM_SECTION"))) void Delay_Loop(uint32_t count)
{
    while(count--);
}

4. 디버거 소스 결합 연동 및 로드 스크립트 설정법 (.ini 파일 구성)

Keil MDK에서 ITCM 주소 대역의 코드를 정상적으로 디버깅하려면, 디버그 세션 개시 시점에 메모리 매핑 기하 정보를 디버거에 명시적으로 주입하는 초기화 매크로 스크립트 파일(.ini)을 작성하여 지정해야 합니다.

[Debug_Initialization.ini 파일 구성 내용]

// 1. 메모리 맵 재구성 선언: 디버거 내부 가상 머신에 ITCM 영역 활성화 정보 명시
MAP 0x00000000, 0x0000FFFF READ WRITE EXEC     // ITCM 영역 읽기/쓰기/실행 권한 부여
MAP 0x20000000, 0x2001FFFF READ WRITE          // 일반 SRAM 영역
// 2. 부팅 리셋 핸들러 가동 후 타겟의 실행 심볼 로딩
LOAD %L INCREMENT // 디버그 심볼 정보(.axf)를 현재 메모리 상태 위에 가산 형태로 로딩
// 3. 프로그램 카운터(PC) 및 스택 포인터 레지스터 강제 동기화
PC = 0x00000000;  // 시작점 복구 주소 강제 지정

설정 방법

  1. Keil 옵션 창(Options for Target)의 Debug 탭으로 진입합니다.
  2. 우측 상단의 Initialization File 선택 항목에서 위에서 만든 Debug_Initialization.ini 파일을 등록합니다.
  3. 이 상태로 디버그 세션을 시작(F5)하면 디버거가 자동으로 심볼 주소를 맵핑하여 ITCM 영역 실행 중에도 C 소스 코드가 완벽히 연동 및 마킹됩니다.

5. 임베디드 FAE 리스크 분석 및 예방 대책

하드웨어 부트 스타트업 복사 루틴 누락 리스크

링커 스크립터 파일(.sct)에 ITCM 영역을 지정한 경우, 런타임 시작 시 플래시(Load Region)의 원본 함수 바이너리를 ITCM 물리 램 메모리(Execution Region)로 전송하는 복사 코드(Startup Copy Section)가 반드시 실행되어야 합니다. 만약 스타트업 어셈블리(.s)나 __main 기동 시퀀스가 생략되고 해당 복사 루틴이 동작하지 않은 상태에서 ITCM의 함수(Delay_Loop)를 강제 호출하면, 초기화되지 않은 메모리 영역(Trash data)을 실행하려다 하드웨어 폴트(Hard Fault) 예외가 나면서 CPU가 즉시 정지하게 됩니다. 반드시 빌드 후 맵 파일(.map)에서 ITCM 복사 엔트리가 동작하고 있는지 바이트 크기를 교차 검증하십시오.

인터럽트 벡터 테이블 배치 충돌 예외

ITCM의 물리 시작 번지는 아키텍처상 부팅 인터럽트 벡터 테이블(Vector Table) 주소와 겹치는 경우가 있습니다. 부트 인터럽트가 매핑되는 주소 공간을 침범하여 코드를 채우면 전원 부팅 인터럽트 처리가 실패하게 되므로, 벡터 오프셋 주소를 감안하여 ITCM 내에서도 코드가 보관될 안전한 베이스 주소를 정의하고 가동하십시오.

6. 참고 자료 및 레퍼런스 (References)

본 기술 가이드는 Arm Compiler (ARMCLANG) v6.x 및 GCC Compiler 공식 링커 명세서 규격과 Cortex-M4/M7 하드웨어 가이드의 Tightly Coupled Memory(TCM) 주소 매핑 설정을 기반으로 작성되었습니다. 또한 Keil MDK-ARM 디버거의 디스크립터 초기화 매뉴얼과 누보톤 디버깅 기술지원 데이터베이스의 소스 매칭 오류 리스크 교정 조치 문서를 검증하여 기록한 FAE 전용 기술 자료입니다.
