1. 개요 및 배경

누보톤 N76E003(18KB Flash)과 MS51 시리즈(8KB, 16KB 또는 32KB Flash)는 8비트 마이크로컨트롤러(MCU)입니다.

하지만 Keil C51 컴파일러의 평가판(Evaluation) 버전은 오브젝트 코드 크기가 2KB로 제한됩니다. 2KB가 넘는 프로그램은 컴파일·어셈블·링크가 되지 않습니다.

이 문제를 우회하는 방법으로, 윈도우뿐만 아니라 리눅스 및 맥OS 환경에서도 쓸 수 있는 무료 오픈소스 컴파일러인 SDCC(Small Device C Compiler)와 VS Code 조합으로 8051 펌웨어를 빌드할 수 있습니다.

이 가이드북은 누보톤의 표준 Keil C51 기반 BSP 소스코드를 오픈소스 컴파일러인 SDCC 규격으로 마이그레이션하기 위한 C 코드 문법 매핑 테이블과 핵심 이식 가이드라인을 제시합니다.

2. Keil C51과 SDCC 컴파일러 문법 변환 규격 (Syntax Mapping)

8051 용 C 컴파일러는 특수 기능 레지스터(SFR)와 여러 메모리 영역(SRAM, Flash)을 지정하는 고유 키워드를 사용합니다. 두 컴파일러 간의 문법 차이를 규격별로 정리한 대조표입니다.

특수 기능 레지스터 (SFR) 정의 방식

  • Keil C51: sfr P0 = 0x80;
  • SDCC: __sfr __at (0x80) P0;

단일 비트 레지스터 (SFR Bit) 정의 방식

  • Keil C51: sbit P05 = P0^5; 또는 sbit P05 = 0x85;
  • SDCC: __sbit __at (0x85) P05;

인터럽트 서비스 루틴 (ISR) 선언 방식

  • Keil C51: void Timer0_ISR(void) interrupt 1
  • SDCC: void Timer0_ISR(void) __interrupt (1)

메모리 영역 키워드 지정 (SRAM 데이터)

  • Keil C51: data (내부 기본 SRAM), xdata (확장 SRAM, N76E003 은 칩 내부 XRAM 768바이트), pdata (페이징 SRAM)
  • SDCC: __data, __xdata, __pdata

상수 테이블 정의 (Flash 저장공간)

  • Keil C51: unsigned char code table[] = { ... };
  • SDCC: __code unsigned char table[] = { ... };

3. BSP 헤더 파일 리팩토링 및 맵핑 기법

누보톤 공식 8051 BSP는 sfr 및 sbit 키워드로 레지스터를 정의한 헤더 파일(N76E003.h 또는 MS51_8K.h·MS51_16K.h·MS51_32K.h)을 제공합니다. 다른 컴파일러용으로 작성된 이런 헤더는 SDCC 와 호환되지 않으며, 특히 sfr P0 = 0x80; 구문은 SDCC 에서 경고 없이 P0 라는 변수에 0x80 을 대입하는 코드로 컴파일됩니다.

이 문제를 해결하기 위해 해외 오픈소스 라이브러리(N76E003-SDCC-BSP)는 누보톤 N76E003 BSP 를 SDCC 용으로 이식하여, 레지스터를 SDCC 문법(__sfr __at, __sbit __at)으로 직접 정의한 헤더를 제공합니다. Keil 과 SDCC 를 한 소스에서 함께 빌드해야 한다면, SDCC 에 포함된 compiler.h 처럼 컴파일러 매크로(SDCC 는 __SDCC 를 항상 정의)를 감지하여 레지스터 정의를 나누는 공용 헤더를 쓸 수 있습니다. 누보톤 N76E003 BSP v2.0 도 numicro_8051.h 에서 컴파일러 매크로에 따라 Keil·IAR·SDCC 용 헤더를 골라 포함합니다.

[Keil 및 SDCC 호환 헤더 파일 설계 구성 예시]

#ifdef __SDCC
// SDCC 컴파일러 전용 레지스터 정의
#define SFR(name, addr) __sfr __at (addr) name
#define SBIT(name, addr) __sbit __at (addr) name
#else
// Keil C51 컴파일러 전용 레지스터 정의
#define SFR(name, addr) sfr name = addr
#define SBIT(name, addr) sbit name = addr
#endif
// 공용 매크로를 활용한 레지스터 지정 예시
SFR(P0, 0x80);
SBIT(P05, 0x85);

4. 실제 구동 코드 변환 비교 (Keil vs SDCC)

LED(P0.5) 핀의 상태를 토글하는 실제 동작 소스코드를 두 컴파일러 포맷으로 대조한 사례입니다.

A. Keil C51 기준 원본 소스코드

#include "N76E003.h"
#include "Function_Define.h"
#include "Delay.h"

void main(void)
{
    P05_PushPull_Mode;
    while(1)
    {
        P05 = ~P05;
        Timer3_Delay100ms(5);
    }
}

B. SDCC 컴파일러 규격 이식 소스코드

#include "N76E003_SDCC.h" // Keil 용 헤더를 SDCC 문법으로 바꾼 예시 헤더 (파일명은 예시)

void main(void)
{
    // P0.5 를 푸시풀 모드로 설정 (함수가 아니라 매크로이므로 괄호를 붙이지 않음)
    P05_PushPull_Mode;
    while(1)
    {
        P05 = ~P05; // 핀 제어
        Timer3_Delay100ms(5);
    }
}

5. 임베디드 FAE 리스크 분석 및 예방 대책

메모리 모델(Memory Model) 불일치로 인한 오작동

SDCC는 컴파일 시 기본적으로 Small 메모리 모델을 채택하며, 이때 주소 공간을 따로 지정하지 않은 변수는 내부 RAM 에 배치됩니다. 8051 아키텍처의 특성상 내부 직접 SRAM(data 영역)은 하위 128바이트에 불과하므로(N76E003 의 내부 SRAM 은 총 256바이트이며 상위 128바이트는 간접 주소 지정 영역입니다), 전역 변수나 지역 변수가 늘어나면 data 영역이 부족해질 수 있습니다. 메모리가 부족하거나 메모리 영역이 겹치면 링커가 경고나 오류를 내며, .map·.mem 파일에서 메모리 배치를 확인할 수 있습니다.

변수가 많아질 경우 SDCC 컴파일 옵션에 --model-large를 지정하면, 주소 공간을 따로 지정하지 않은 변수(재진입 함수가 아니면 함수 인자와 지역 변수 포함)가 xdata 영역에 배치됩니다. 이 옵션을 쓰면 프로젝트의 모든 소스 파일을 같은 옵션으로 컴파일하고 링크할 때도 같은 옵션을 주어야 합니다. 서로 다른 메모리 모델로 컴파일한 모듈을 섞으면 결과를 예측할 수 없습니다.

어셈블리 인라인 구문 컴파일 오류

누보톤 공식 BSP 의 TA 보호 레지스터 해제 코드는 TA=0xAA; TA=0x55; 를 쓰는 C 매크로로 작성되어 있어 그대로 이식됩니다. 다만 achilikin 의 SDCC 이식본은 클럭 전환 레지스터처럼 TA 보호가 걸린 곳에서 SDCC 가 추가 명령을 끼워 넣어 보호가 깨지지 않도록 __asm__("orl _CKSWT,#0x20") 형식의 인라인 어셈블리를 사용합니다. Keil 은 #pragma ASM 으로, SDCC 는 __asm__("...") 또는 __asm ~ __endasm 구문으로 어셈블리를 감싸므로, 인라인 어셈블리가 있는 부분은 SDCC 형식으로 바꿔 주어야 정상 빌드가 가능합니다.
