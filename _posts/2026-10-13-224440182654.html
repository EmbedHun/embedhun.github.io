MA35D1 BSP 를 빌드하면 TF-A, U-Boot, 커널 같은 이미지가 여러 개 나옵니다. NuWriter 의 Pack 기능은 이 이미지들을 저장 위치(offset)와 함께 pack.bin 하나로 묶어서 write 명령 한 번으로 쓸 수 있게 해 주고, Unpack 은 묶은 파일을 다시 풀어 줍니다. 매뉴얼은 양산 단계에서 쓸 수 있다고 설명합니다. 이 글에서 "매뉴얼"이라고만 적은 것은 Nuvoton 의 MA35 Series NuWriter User Manual Rev 1.05 (파일 이름 UM_EN_MA35_NuWriter.pdf) 입니다.

이 글은 Pack/Unpack 을 직접 실행해 본 기록입니다. Pack/Unpack 은 보드가 필요 없는 오프라인 기능이라 PC 에서 전부 실행했습니다. 보드에 쓰는 단계(Download)는 하지 않았습니다. 만든 pack.bin 은 Write 로 보드에 씁니다. 매뉴얼 6.6절의 예는 -w nand pack.img 이고, pack 이미지는 안에 offset 정보가 이미 들어 있어서 offset 을 적지 않습니다. GUI 에서는 Download 탭에서 저장 매체(매뉴얼 예는 NAND)를 고르고, Browse 로 이미지 파일을 고른 뒤, 파일에 맞는 Image type 을 고르고 Write 를 누릅니다. 매뉴얼 7.2.1절의 예에서 demo.bin 은 Pack Image 입니다. 이미지 주소는 Data 타입일 때만 입력합니다.

1. Develop mode 로 바꾸기

NuWriter GUI 를 처음 열면 Attach 와 Download 탭만 보입니다. 메뉴에서 Mode → Develop mode 를 선택하면 Convert 와 Pack/Unpack 탭이 추가됩니다.

Develop mode 선택 후 Pack/Unpack 탭. Pack 과 Unpack 하위 탭이 있습니다.

2. pack.json 만들기

어떤 이미지를 어느 offset 에 둘지 pack.json 에 적습니다. 항목은 offset, file, type 세 개이고, type 은 매뉴얼에 예약값이라 0 으로 두라고 되어 있습니다. 연습용으로 4KB(0x11 로 채움)와 8KB(0x22 로 채움) 파일 두 개를 만들어 아래처럼 적었습니다.

{"image": [

{"offset": "0x500000", "file": "image1.bin", "type": 0},

{"offset": "0x50A000", "file": "image2.bin", "type": 0}

]}

GUI 에서는 Image Amout(화면에 적힌 표기 그대로입니다) 칸에 이미지 개수를 넣고 Generate pack.json 을 누르면 입력 창으로 만들 수도 있습니다. 저는 위 파일을 직접 만들어 사용했습니다.

3. Pack 실행

Pack 탭에서 pack.json 의 Browse 로 파일을 고르고 Pack 을 누릅니다. CLI 로는 아래와 같습니다.

NuWriter_MA35.exe -p pack.json

실행하면 월일-시각 이름의 폴더가 만들어지고 그 안에 pack.bin 이 생깁니다.

Pack 실행 후 로그. pack.bin 이 만들어졌다는 메시지가 나옵니다.

제 PC 에서는 "Create symbolic folder pack failed" 가 먼저 표시됐지만 pack.bin 은 정상적으로 만들어졌습니다. 매뉴얼에는 최신 폴더를 가리키는 pack 링크를 만든다고 되어 있는데, 메시지는 pack 이라는 이름의 링크를 만들지 못했다는 뜻입니다. 매뉴얼 2장은 "Fail to create symbolic folder" 문제가 있으면 Windows 의 Developer Mode 를 켜라고 안내합니다. 실제로 Developer Mode 를 켜고 같은 명령을 다시 실행하니 이 메시지가 나오지 않았고, 결과 폴더를 가리키는 pack 링크가 만들어졌습니다. 이 글의 실행 결과는 켜기 전의 것입니다.

GUI 로 만든 pack.bin 과 CLI 로 만든 pack.bin 은 바이트 단위로 같았습니다.

4. pack.bin 안을 보면

매뉴얼 5장에 pack 이미지 형식 표가 있고, 이번에 만든 파일도 그 표와 맞았습니다. 이미지는 4096 바이트와 8192 바이트라 합이 12288 바이트인데 pack.bin 은 12368 바이트(0x3050)였습니다. 맨 앞 16바이트는 마커(NVT), CRC32, 이미지 개수(2), 예약 칸이고, 이미지마다 length, offset, type, 예약 칸이 붙은 뒤 데이터가 이어집니다. 첫 이미지 데이터는 0x28 위치에서, 두 번째는 0x1048 위치에서 시작했습니다. 각 항목이 16바이트 경계에서 시작해서 이미지 사이와 파일 끝에 0xFF 로 채운 빈 칸이 있습니다. offset(0x500000)은 pack.bin 안에 값으로 들어 있을 뿐이고, 파일이 offset 위치까지 늘어나지는 않습니다. CRC32 값은 파일의 8번째 바이트부터 끝까지 계산한 값과 같았습니다.

5. Unpack 으로 풀기

Unpack 탭에서 PACK_IMAGE 의 Browse 로 pack.bin 을 고르고 Unpack 을 누릅니다. CLI 는 아래와 같습니다.

NuWriter_MA35.exe -o unpack -p pack.bin

Unpack 실행 후 로그. crc32 를 확인하고 풀린 폴더 이름을 보여 줍니다.

로그에 "check pack file crc32" 가 나오고, 폴더에는 img0.bin 과 img1.bin 이 생깁니다. 원래 파일 이름은 복원되지 않고 순서대로 번호가 붙습니다. 두 파일 모두 원본 image1.bin, image2.bin 과 내용이 같았습니다. 화면에는 CRC disabled 체크 항목도 있는데, 이 항목은 사용해 보지 않았습니다.

6. stuff 옵션 - 빈 곳을 0xFF 로 채우기

매뉴얼은 pack 에 stuff 옵션이 있어, 이미지 사이를 0xFF 로 채운 이미지 하나를 만들 수 있다고 설명합니다. GUI 에서는 Pack 탭의 stuff pack 체크이고, CLI 로는 아래처럼 실행했습니다.

NuWriter_MA35.exe -o stuff -p pack.json

결과는 5292032 바이트(0x50C000)였고, 내용은 다음과 같았습니다.

  • 0x000000 ~ 0x4FFFFF : 전부 0xFF
  • 0x500000 ~ 0x500FFF : image1.bin (0x11)
  • 0x501000 ~ 0x509FFF : 전부 0xFF
  • 0x50A000 ~ 0x50BFFF : image2.bin (0x22)

즉 pack.json 의 offset 이 파일 안의 실제 위치가 됩니다. 매뉴얼에는 일부 라이터에서 이렇게 만든 이미지를 SPI NOR 에 쓸 수 있고, NAND 나 SPI NAND 에는 쓰면 안 된다고 되어 있습니다. 배드 블록 때문에 이미지 위치가 밀릴 수 있기 때문입니다.

7. BSP 에 들어 있는 pack.json

매뉴얼 7.5절에 따르면 MA35 BSP 는 빌드할 때 TF-A BL2, BL31, BL32, U-Boot BL33, 리눅스 커널을 담은 pack 파일을 만들고, NuWriter 가 이 파일을 바로 쓸 수 있습니다. NAND 용 예시는 pack-nand.json 이고 위치는 다음과 같습니다.

  • Buildroot : buildroot/board/nuvoton/ma35d1/nuwriter/pack-nand.json
  • Yocto : build/tmp-glibc/deploy/images/numaker-som-ma35d16a81/nuwriter/pack-nand.json

같은 절에는 이미지 하나만 다시 쓰는 방법도 있습니다. NAND 를 선택하고 이미지 type 을 Data 로 둔 뒤 offset 을 넣어 Write 를 누르는 방식이고, 매뉴얼의 offset 예는 fip.bin-nand 0x100000, Image(리눅스 커널) 0x400000, bl2.bin 0xE0000 입니다.

정리

  • Pack/Unpack 은 보드 없이 PC 에서 실행되는 오프라인 기능이고, Mode → Develop mode 에서 탭이 나타납니다.
  • pack.json 에 offset, file, type 을 적고 NuWriter_MA35.exe -p pack.json 으로 pack.bin 을 만듭니다.
  • Unpack 으로 풀면 img0.bin, img1.bin 처럼 번호가 붙고 내용은 원본과 같습니다.
  • stuff 옵션은 offset 위치대로 0xFF 를 채운 이미지를 만듭니다. NAND 용으로는 쓰지 않습니다.
