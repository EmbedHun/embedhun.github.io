1. 개요 및 배경

MA35D1 시리즈는 듀얼 Cortex-A35 코어를 탑재하며, 하드웨어 UART 는 최대 9.5 Mbps 보오레이트를 지원합니다. (9.5 Mbps 는 Bare-metal 비OS 코드 기준 검증 결과이며, 이 글의 Linux 구성은 6 Mbps 기준입니다)

MA35D1 TRM — 6.24.5.8 UART Function Mode 설명(UART 보오레이트 상한)

    이 가이드북은 리눅스 커널 드라이버의 FIFO 트리거 레벨 조정, 디바이스 트리(DTS) 클럭 소스 강제 정의, 그리고 C 코드 상에서 비표준 보오레이트(BOTHER ioctl) 설정을 통해 6 Mbps 시리얼 통신을 에러 없이 구동하는 실무 가이드를 제시합니다.

    2. 해결 3단계 프로시저 (Solution Blueprint)

    1단계: 리눅스 커널 시리얼 드라이버의 FIFO 트리거 레벨 최적화

    FIFO 수신 트리거 레벨을 기본값(0x10, 4바이트)보다 높은 0x30(14바이트)으로 설정하도록 드라이버 코드를 수정합니다.

    수정 파일: drivers/tty/serial/ma35d1_serial.c

    수정 함수: ma35d1serial_startup()

    • serial_out(up, UART_REG_FCR, serial_in(up, UART_REG_FCR) | 0x10 | 0x20000);
    + // [MOD] FIFO 수신 트리거 임계치를 0x30(14바이트, 수신 버퍼가 더 찰 때까지 인터럽트 대기)으로 수정
+ serial_out(up, UART_REG_FCR, serial_in(up, UART_REG_FCR) | 0x30 | 0x20000);

    참고: 트리거 레벨을 0x30으로 변경하면 수신 FIFO 에 14바이트가 쌓였을 때 수신 데이터 인터럽트 플래그(RDAIF)가 세트됩니다(기본값 0x10 은 4바이트).

    MA35D1 TRM — UART_FIFO 레지스터와 RFITL 필드 설명(중간 생략)

    2단계: 디바이스 트리(DTS) UART 부모 클럭 소스 변경

    UART10 의 클럭 소스를 SYSCLK1 을 2분주한 시스템 클럭(SYSCLK1_DIV2)으로 지정합니다.

    MA35D1 TRM — CLK_CLKSEL3 레지스터와 UART10SEL 필드 설명(중간 생략)

    수정 파일: arch/arm64/boot/dts/nuvoton/ma35d1.dtsi

    수정 타겟: uart10 (사용할 UART 인스턴스에 맞춰 수정)

    uart10: serial@407A0000 {
    compatible = "nuvoton,ma35d1-uart";
    reg = <0x0 0x407A0000 0x0 0x10000>;
    interrupts = <GIC_SPI 95 IRQ_TYPE_LEVEL_HIGH>;
    clocks = <&clk UART10_GATE>;
    port-number = <10>;
    pdma-enable = <0>;
    // [MOD] 부모 클럭(Parent Clock) 소스를 시스템 클럭(SYSCLK1/2)으로 인가
    assigned-clocks = <&clk UART10_MUX>;
    assigned-clock-parents = <&clk SYSCLK1_DIV2>;
    status = "okay"; // disabled에서 okay로 변경하여 활성화
};

    3단계: C 애플리케이션에서 비표준 고속 보오레이트(6 Mbps) 설정

    일반적인 리눅스 termios API(B115200, B921600 등)는 6,000,000bps와 같은 비표준 보오레이트를 인자로 직접 지원하지 못합니다.

    따라서 asm/termbits.h에 정의된 BOTHER 플래그와 ioctl 명령인 TCSETS2를 사용해 커스텀 속도를 커널에 직접 전달해야 합니다.

    #include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <asm/termbits.h>  // 표준 termios.h 대신 asm/termbits.h 필요

int open_high_speed_port(const char *portname)
{
    int fd;
    struct termios2 tio; // termios2 구조체 사용 필수
    // 1. 포트 열기
    fd = open(portname, O_RDWR | O_NOCTTY | O_NDELAY);
    if (fd < 0) {
        printf("Open serial port %s failed\n", portname);
        return -1;
    }
    // 2. 현재 termios2 설정 읽기
    if (ioctl(fd, TCGETS2, &tio) < 0) {
        printf("TCGETS2 ioctl failed\n");
        close(fd);
        return -1;
    }
    // 3. 입출력 통신 속도 설정을 위한 마스크 수정
    tio.c_cflag &= ~CBAUD;
    tio.c_cflag |= BOTHER;          // 비표준 커스텀 보오레이트 모드 지정
    tio.c_ispeed = 6000000;         // 수신 속도: 6,000,000 bps (6 Mbps)
    tio.c_ospeed = 6000000;         // 송신 속도: 6,000,000 bps (6 Mbps)
    // 4. 기본적인 Raw Mode 터미널 옵션 정의
    tio.c_cflag &= ~(CSIZE | PARENB | CSTOPB);
    tio.c_cflag |= CS8 | CLOCAL | CREAD;
    tio.c_iflag &= ~(IXON | IXOFF | IXANY | ICRNL);
    tio.c_oflag &= ~OPOST;
    tio.c_lflag &= ~(ICANON | ECHO | ECHOE | ISIG);
    // 5. 변경된 termios2 구조체 인가
    if (ioctl(fd, TCSETS2, &tio) < 0) {
        printf("TCSETS2 ioctl failed to apply 6 Mbps\n");
        close(fd);
        return -1;
    }
    printf("Successfully configured %s at 6 Mbps using BOTHER.\n", portname);
    return fd;
}

    3. 검수용 루프백(Loopback) 테스트 쉘 스크립트

    송수신 라인을 쇼트(Short)시킨 상태에서 2,048바이트 크기의 데이터를 100회 연속 에러 없이 전송하는 루프백 안정성을 입증하기 위한 검증 스크립트 예제입니다.

    #!/bin/sh
# 6 Mbps 루프백 연속 테스트 (100회 실행)

    PORT="/dev/ttyS10" # 활성화한 MA35D1 UART 포트 노드 이름

    echo "Starting UART loopback stress test at 6 Mbps on $PORT..."
for i in $(seq 1 100)
do
echo "Round $i / 100 Running..."
# 내부 테스트용 송수신 바이너리 실행
./uart_demo_rx_tx $PORT 6000000 2048
if [ $? -ne 0 ]; then
echo "ERROR: Transmission failure at round $i"
exit 1
fi
sleep 1
done
echo "SUCCESS: All 100 rounds of 6 Mbps UART test passed successfully!"

    4. 임베디드 FAE 리스크 분석 및 예방 대책

    데이터 단편화(Fragmentation) 위험

    수신 FIFO 트리거 레벨을 0x30 (14바이트)으로 높이면, 14바이트 미만의 짧은 데이터 패킷이 수신되었을 때 즉시 인터럽트가 걸리지 않고 버퍼에 잠시 갇힐 수 있습니다. 누보톤 UART 하드웨어에는 데이터 수신이 멈추면 인터럽트를 강제로 발생시키는 수신 타임아웃(Rx Timeout) 기능이 제공됩니다. 트리거 레벨 상향 시 반드시 드라이버 상에서 UART Rx Timeout 인터럽트가 활성화 상태인지 교차 검증하십시오.

    RS-485 트랜시버 방향 제어

    트랜시버의 DE(Driver Enable) 핀을 소프트웨어(GPIO 제어)로 전환하는 대신, MA35D1 UART 드라이버가 지원하는 RS-485 자동 방향 제어(Auto Direction, nRTS 핀을 DE 에 연결) 기능을 사용할 수 있습니다.
