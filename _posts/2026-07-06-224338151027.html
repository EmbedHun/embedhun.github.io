1. 개요 및 배경

ISP(In-System Programming)는 마이크로컨트롤러를 시스템에서 떼어내지 않고 소프트웨어 제어로 플래시 메모리를 다시 프로그래밍하는 기능입니다.

N76E003 의 프로그램 메모리는 APROM(Application ROM)과 LDROM(Loader ROM)이라는 하드웨어적으로 독립된 두 블록으로 나뉩니다.

이 가이드북은 N76E003 의 APROM/LDROM 구조와 ISP 진입 시 부팅 제어 흐름을 설명합니다.

2. 메모리 파티션 맵 구성 (APROM vs LDROM)

두 영역은 하드웨어적으로 독립된 블록이며, 각각 0000H 번지부터 시작하는 주소를 가집니다.

N76E003 데이터시트 — Figure 5.1-1 N76E003 Program Memory Map

APROM (Application ROM)

  • 용도: 사용자의 메인 애플리케이션 제어 소프트웨어 코드가 보관되는 메인 스토리지 공간.
  • N76E003 기준 크기: 최대 18KB 대역 (주소 범위: 0x0000 ~ 0x47FF)

LDROM (Loader ROM)

  • 용도: ISP 용 부트 코드(Boot Code)를 저장하는 공간. 부트 코드는 APROM 영역과 CONFIG 바이트를 갱신할 수 있으며, 누보톤은 UART 포트를 통한 ISP 펌웨어를 제공합니다.
  • N76E003 기준 크기: 최대 4KB 대역 (주소 범위: 0x0000 ~ 0x0FFF, 독립된 별도 주소 맵으로 할당)

3. CONFIG 레지스터 설정 및 부트 타겟 제어 (CBS 비트)

전원 인가 직후(Power-on Reset) CPU의 프로그램 카운터(PC) 레지스터가 어느 메모리 영역의 0번지 코드를 가리키고 부팅을 시작할지 결정하는 열쇠는 바로 사용자 구성 비트인 CONFIG0 레지스터의 CBS 비트입니다.

N76E003 데이터시트 — CONFIG0 레지스터와 CBS 비트

부팅 시작 위치 설정 제어 규격 (CONFIG0의 CBS 비트)

  • CBS = 1 (APROM 부팅): 소프트웨어 리셋을 제외한 리셋 후 APROM 에서 부팅합니다.
  • CBS = 0 (LDROM 부팅): 소프트웨어 리셋을 제외한 리셋 후 LDROM 에서 부팅합니다.

4. CHPCON 레지스터 기반 ISP(IAP) 제어 및 소프트웨어 리셋 C 코드

메인 앱(APROM) 실행 도중 특정 UART 패킷(예: 업그레이드 시작 플래그)을 수신하면 하드웨어 리셋 없이 소프트웨어 명령으로 LDROM(부트로더)으로 복귀하는 CHPCON 레지스터 제어 및 소프트웨어 리셋 시퀀스 구현 C 소스코드입니다.

#include "N76E003.h"
#include "Common.h"

void Go_To_LDROM_ISP(void)
{
    // 1. Timed Access(TA) 시퀀스: 보호된 레지스터는 쓰기 직전마다 필요
    TA = 0xAA;
    TA = 0x55;
    // 2. 칩 컨트롤 레지스터(CHPCON) 설정
    // IAP(ISP) 기능 활성화 비트 세팅
    // CHPCON 레지스터의 IAPEN 비트(bit0, IAP Enable)를 켭니다.
    CHPCON |= 0x01;
    // 3. CHPCON 의 BS 비트(bit1)를 1로 설정하여 다음 리셋 시 LDROM에서 부팅하도록 지정 (쓰기마다 TA 시퀀스 필요)
    TA = 0xAA;
    TA = 0x55;
    CHPCON |= 0x02;
    // 4. 소프트웨어 리셋 트리거 발생
    // CHPCON 레지스터의 SWRST 비트를 1로 설정하여 소프트웨어 리셋 발생 (BS 는 유지되므로 LDROM에서 부팅)
    TA = 0xAA;
    TA = 0x55;
    CHPCON |= 0x80;
}

void main(void)
{
    // UART0 수신 대기 루프
    while(1)
    {
        // 0xA5 바이트가 UART로 수신되면 ISP 모드(LDROM)로 전환 실행
        if (Receive_Data_From_UART0() == 0xA5)
        {
            Go_To_LDROM_ISP();
        }
    }
}

5. 임베디드 FAE 리스크 분석 및 예방 대책

IAP 오제어로 인한 CONFIG 바이트 오기록 리스크

IAP 로 CONFIG 바이트를 잘못 기록하면 LOCK 비트가 0(칩 잠금)으로 바뀌어, 병렬 라이터나 ICP 로 읽은 플래시 내용이 모두 FFH 로 보이고 CONFIG 바이트를 개별로 지우거나 쓸 수 없게 될 수 있습니다. 칩이 손상되는 것은 아니며, Whole Chip Erase 를 실행하면 잠금이 풀립니다. 다만 이때 플래시 메모리와 CONFIG 의 내용이 모두 지워지므로 펌웨어를 다시 써 넣어야 합니다. 플래시 쓰기 작업 수행 시에는 VDD 전원을 동작 전압 범위(2.4V~5.5V) 안으로 유지하십시오. IAP 는 HIRC 가 동작해야 하며, IAPEN(CHPCON.0)을 켜면 타이밍 제어를 위해 HIRC 가 자동으로 켜집니다.

LDROM 과 APROM 의 인터럽트 벡터 분리

N76E003 이 LDROM 에서 부팅하면 CPU 는 프로그램 카운터 0000H 를 LDROM 시작 주소로 잡고, LDROM 을 독립된 프로그램 메모리로 취급하며, 모든 인터럽트 벡터도 APROM 과 독립됩니다. LDROM 에서 APROM 갱신을 마친 뒤에는 CHPCON 의 BS 비트를 0으로 쓰고 소프트웨어 리셋(SWRST)을 실행하여 APROM 에서 다시 부팅하도록 부팅 시퀀스를 설계하십시오.
