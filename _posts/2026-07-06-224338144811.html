1. 개요 및 배경

누보톤 N76E003 평가용 보드인 NuTiny-SDK-N76E003-V2.1 보드는 MCU 칩과 디버깅 라이터기인 Nu-Link-Me 장치가 하나의 기판에 통합된 편리한 개발 보드입니다. 이 보드는 PC와 USB 케이블로 연결 시 디버깅뿐만 아니라 가상 COM 포트(Virtual COM Port) 통신을 지원하며, VCOM Driver 를 설치하고 Nu-Link-Me 구역의 SW3 스위치를 켜면 윈도우에서 일반 COM 포트처럼 접근할 수 있어 간편한 디버그 메시지 모니터링이 가능합니다.

그러나 수많은 개발자들이 N76E003 UART 테스트 코드를 올바르게 빌드하고 PC의 터미널 프로그램을 해당 포트로 열었음에도 수신 메시지가 전혀 나타나지 않고 송신 문자도 MCU로 들어가지 않는 직렬 통신 먹통 오류에 직면합니다.

이 가이드북은 NuTiny 보드의 VCOM 기능이 Nu-Link-Me 구역의 SW3 스위치로 켜고 끄는 방식이라는 점을 바탕으로, 스위치가 꺼져 있을 때 통신이 되지 않는 원인과 통신 링크를 정상 복구하는 실무 해결책을 제공합니다.

2. 오작동 원인 분석 (VCOM 스위치 OFF 상태)

가장 먼저 확인할 하드웨어 원인은 Nu-Link-Me 구역의 VCOM 기능 스위치(SW3)가 OFF 로 되어 있는 경우입니다.

Nu-Link-Me 의 가상 COM 포트는 온보드 N76E003AT20 의 UART0(TXD_0: P0.6, RXD_0: P0.7)에 연결되며, 이 기능은 Nu-Link-Me 구역의 4극 스위치 SW3 로 켜고 끕니다. SW3 의 4개 스위치를 모두 OFF 로 두면 VCOM 기능이 비활성화되어 PC 터미널과 통신이 되지 않습니다.

따라서 VCOM 통신을 사용하려면 SW3 의 4개 스위치를 모두 ON 으로 설정해야 합니다. VCOM 을 쓰지 않을 때는 모두 OFF 로 둡니다.

3. 하드웨어 설정 단계 (SW3 스위치 ON)

NuTiny-SDK-N76E003-V2.1 보드의 Nu-Link-Me 구역에는 가상 COM 포트 기능을 켜고 끄는 4극 스위치 SW3 가 있습니다.

복구 절차

  1. 보드의 전원을 컴퓨터에서 완전히 분리합니다.
  2. Nu-Link-Me 구역의 SW3 스위치를 찾습니다. SW3 는 4개의 스위치(1~4)로 이루어져 있습니다.
  3. SW3 의 1~4번 스위치를 모두 ON 위치로 올립니다. 모두 ON 이면 VCOM 이 활성화되고, 모두 OFF 이면 비활성화됩니다.
  4. 스위치가 ON 이 되면 Nu-Link-Me 의 가상 COM 포트가 N76E003 의 UART0(TXD: P0.6, RXD: P0.7)에 연결됩니다. 처음 사용하는 PC 라면 VCOM Driver 를 먼저 설치해야 하며, 드라이버는 NuMicroDVD 의 Software Utilities 폴더에서 받을 수 있습니다.

4. UART0 펌웨어 초기화 검증 소스코드

N76E003 보드에서 VCOM 도통을 확인하기 위해 38400bps 속도로 문자 데이터를 연속 송신하는 표준 C 코드 템플릿입니다. 내장 16MHz HIRC 에서는 보레이트 오차 때문에 38400bps 이하를 권장하므로 이 예제는 38400bps 로 구성했습니다.

#include "N76E003.h"

void UART0_Init_38400(void)
{
    // 1. P0.6(TXD)/P0.7(RXD) 핀 모드 설정: PxM1.n=0, PxM2.n=0 (준양방향)
    P0M1 &= ~0xC0;
    P0M2 &= ~0xC0;
    // 2. 타이머 1을 UART0의 보오레이트(Baud Rate) 발생기로 지정
    SCON = 0x50;     // UART0 모드 1 (8비트 데이터, 가변 속도), 수신 인에이블
    TMOD |= 0x20;    // 타이머 1 모드 2 (8비트 자동 재로드 타이머)
    // 3. 38400bps 보오레이트 설정 (내장 16MHz HIRC, SMOD=1, T1M=1: 보레이트 = FSYS/16/(256-TH1))
    PCON |= 0x80;    // SMOD=1 (UART0 배속)
    CKCON |= 0x10;   // T1M=1 (타이머 1 클럭 = FSYS)
    T3CON &= 0xDF;   // BRCK=0 (UART0 보레이트 클럭원 = 타이머 1)
    TH1 = 256 - (16000000UL / (16UL * 38400UL));
    TR1 = 1;         // 타이머 1 기동
    TI = 1;          // 첫 번째 전송 트리거용 송신 플래그 인에이블
}

void Send_Char_UART0(uint8_t data)
{
    while (!TI);    // 이전 버퍼 송신 완료 대기
    TI = 0;         // 송신 플래그 클리어
    SBUF = data;    // 직렬 포트 버퍼에 데이터 적재
}

void main(void)
{
    // UART 설정 (참고: WDT·BOD 같은 TA 보호 SFR 을 쓸 때는 TA=0xAA; TA=0x55; 를 먼저 써야 하며, UART 설정에는 필요 없음)
    UART0_Init_38400();
    while(1)
    {
        // PC 화면으로 'U' (0x55) 문자를 100ms마다 송신
        Send_Char_UART0('U');
        Timer0_Delay100ms(1);
    }
}

5. 임베디드 FAE 리스크 분석 및 예방 대책

VCOM 활성화 후 I/O 핀 충돌 리스크

SW3 를 ON 으로 켜면 N76E003 의 P0.6 및 P0.7 핀이 Nu-Link-Me 의 가상 COM 포트와 연결된 상태가 됩니다. 만약 펌웨어 코드 내부에서 실수로 P0.6이나 P0.7 핀의 속성을 강제 푸시풀 출력 모드(Push-pull Output Mode)로 설정하고 전압 신호(Low/High)를 제어하려고 시도하면, 디버거 쪽 직렬 회로 출력과 충돌이 발생해 오작동이 유발될 수 있습니다. VCOM 사용 중에는 해당 핀들을 절대로 일반 GPIO 제어 용도로 중복 사용하지 마십시오.

컴퓨터 직렬 터미널 버그 및 세션 락 오류

터미널 연결 시 가상 COM 드라이버의 세션이 잠겨 문자 전송이 중간에 멈추는 에러가 발생할 수 있습니다. 스위치 설정을 바꾼 직후에는 포트 접속을 시도하기 전 장치 관리자에서 드라이버를 재설정하거나 터미널 툴(예: Tera Term, Putty 등)의 흐름 제어(Flow Control) 옵션을 하드웨어/소프트웨어 제어 없이 없음(None) 상태로 지정하여 프레임 오류가 없는 통신을 유지하십시오.
