1. 개요 및 배경

임베디드 소프트웨어 개발 시, 프로그램이 기동 중에 불규칙하게 하드웨어 오류 예외(Hard Fault)를 일으키며 뻗어버리거나, 변수가 원인 모르게 꼬이는 복잡한 레이스 컨디션(Race Condition) 디버깅은 FAE 엔지니어들에게 가장 해결하기 까다로운 영역입니다.

일반적인 디버깅 방식(Break point 지정 후 한 단계씩 실행)은 CPU의 실시간 신호 제어 시퀀스를 방해하여 버그 재현을 더 어렵게 만듭니다.

이를 해결하기 위해 ARM Cortex-M4 코어를 탑재한 누보톤 M480 시리즈(M487 등)는 CPU 동작을 방해하지 않고 실행한 명령어의 흔적을 실시간으로 고속 캡처하여 스트리밍해 주는 ETM(Embedded Trace Macrocell) 하드웨어 블록을 제공합니다.

특히 누보톤 공식 평가 보드인 NuMaker-ETM-M487 보드는 기판 상에 전용 20핀 ETM 트레이스 커넥터가 장착되어 고급 디버깅 장비를 즉시 사용할 수 있습니다.

이 가이드북은 Keil MDK ARM 빌드 환경과 ULINKpro 디버거를 연결하여, M487 보드에서 ETM을 성공적으로 활성화하고 CPU 실행 이력을 100% 실시간 추적하는 설정 시퀀스를 공유합니다.

2. ETM 동작의 하드웨어 전제 조건 (트레이스 핀 결선)

ETM을 동작시키려면 MCU가 실행하는 초고속 클럭 신호(보통 수십 MHz)에 맞춰 실시간으로 추적 데이터를 디버거 장치로 인계해야 합니다. 이를 위해 Trace CLK 신호선 1개와 Trace Data 신호선 4개(Data 0 ~ Data 3)가 물리적으로 ETM 커넥터와 직결되어 다중 맵핑(MFP) 활성화가 되어 있어야 합니다.

M487 MCU의 전용 트레이스 핀 구성 정보 (PE 대역 포트 지정, 모두 MFP14)

  • TRACE_CLK: PE.12 핀 (트레이스 신호 동기 클럭)
  • TRACE_DATA0: PE.11 핀 (트레이스 데이터 0비트)
  • TRACE_DATA1: PE.10 핀 (트레이스 데이터 1비트)
  • TRACE_DATA2: PE.9 핀 (트레이스 데이터 2비트)
  • TRACE_DATA3: PE.8 핀 (트레이스 데이터 3비트)

3. 펌웨어 내부 다중 기능 핀(MFP) 초기화 설정

M487 시스템 기동 시, 해당 핀들을 일반 GPIO 모드에서 ETM 전용 초고속 트레이스 핀 속성으로 강제 변경해 주어야 디버거 커넥터로 주파수 파형이 흐릅니다. SYS_Init() 단계에 포함되어야 할 C 소스코드 내용입니다.

#include "NuMicro.h"

void ETM_Pin_Configuration(void)
{
    SYS_UnlockReg();
    // 1. PE.12, PE.11, PE.10, PE.9, PE.8 핀의 다중 기능 레지스터(MFP)를 트레이스 신호로 지정
    SYS->GPE_MFPH = (SYS->GPE_MFPH & ~SYS_GPE_MFPH_PE12MFP_Msk) | SYS_GPE_MFPH_PE12MFP_TRACE_CLK;
    SYS->GPE_MFPH = (SYS->GPE_MFPH & ~SYS_GPE_MFPH_PE11MFP_Msk) | SYS_GPE_MFPH_PE11MFP_TRACE_DATA0;
    SYS->GPE_MFPH = (SYS->GPE_MFPH & ~SYS_GPE_MFPH_PE10MFP_Msk) | SYS_GPE_MFPH_PE10MFP_TRACE_DATA1;
    SYS->GPE_MFPH = (SYS->GPE_MFPH & ~SYS_GPE_MFPH_PE9MFP_Msk) | SYS_GPE_MFPH_PE9MFP_TRACE_DATA2;
    SYS->GPE_MFPH = (SYS->GPE_MFPH & ~SYS_GPE_MFPH_PE8MFP_Msk) | SYS_GPE_MFPH_PE8MFP_TRACE_DATA3;
    // 2. 고속 클럭 파형의 왜곡을 방지하기 위해 해당 핀들의 슬루율(Slew Rate)을 High로 변경
    PE->SLEWCTL = (PE->SLEWCTL & ~GPIO_SLEWCTL_HSREN12_Msk) | (GPIO_SLEWCTL_HIGH << GPIO_SLEWCTL_HSREN12_Pos);
    PE->SLEWCTL = (PE->SLEWCTL & ~GPIO_SLEWCTL_HSREN11_Msk) | (GPIO_SLEWCTL_HIGH << GPIO_SLEWCTL_HSREN11_Pos);
    PE->SLEWCTL = (PE->SLEWCTL & ~GPIO_SLEWCTL_HSREN10_Msk) | (GPIO_SLEWCTL_HIGH << GPIO_SLEWCTL_HSREN10_Pos);
    PE->SLEWCTL = (PE->SLEWCTL & ~GPIO_SLEWCTL_HSREN9_Msk) | (GPIO_SLEWCTL_HIGH << GPIO_SLEWCTL_HSREN9_Pos);
    PE->SLEWCTL = (PE->SLEWCTL & ~GPIO_SLEWCTL_HSREN8_Msk) | (GPIO_SLEWCTL_HIGH << GPIO_SLEWCTL_HSREN8_Pos);
    SYS_LockReg();
}

4. Keil MDK Options 설정 및 ULINKpro 드라이버 디렉토리 지정

하드웨어 준비 및 핀 할당 코드를 적용했으면, Keil MDK 프로그램 상에서 디버거 드라이버 속성을 재정의해야 합니다.

설정 프로시저

  1. Keil의 Options for Target (Alt+F7) 창으로 들어갑니다.
  2. Debug 탭으로 진입하여 디버거 종류를 ULINK Pro Cortex Debugger로 선택한 후 옆의 Settings 버튼을 누릅니다.
  3. 세부 설정 내의 Trace 탭으로 이동합니다.
  4. Trace Enable 체크박스를 클릭하여 인에이블시킵니다.
  5. Trace Port 선택박스에서 Sync Trace Port with 4-bit Data Width를 선택합니다. (ETM은 4비트 버스 폭을 사용해 데이터를 내보냅니다.)
  6. Core Clock 주파수를 타겟 M487 보드의 실시간 동작 클럭 속도인 192000000(192MHz)으로 오차 없이 정확히 입력합니다. 이 값이 틀리면 데이터 수집 속도 싱크가 깨져 프레임 오류가 납니다.
  7. ETM Trace Enable 체크 박스에 체크합니다.
  8. 확인(OK)을 누르고 디버그 세션을 실행하면, Keil의 Instruction Trace 윈도우 창이 열리며 CPU가 실행한 수억 줄의 어셈블리 이력과 분기(Branch) 성공/실패 기록이 타임스탬프와 함께 완벽히 수집되기 시작합니다.

5. 임베디드 FAE 리스크 분석 및 예방 대책

트레이스 라인 임피던스 불일치로 인한 데이터 왜곡 리스크

ETM 핀으로 인출되는 트레이스 클럭과 데이터 파형은 100MHz 이상으로 스위칭하므로, 회로 설계 시 선로의 신호선 길이 편차가 심하거나 기생 노이즈가 유입되면 신호 스큐(Skew)가 발생하여 디버거 상에서 패킷 무결성 오류가 납니다. 회로 패턴 설계 시 반드시 트레이스 5핀 라인은 길이를 최대한 동일하게(등장 패턴) 맞추고, 다른 통신 노이즈 전선과 겹치지 않게 솔더 가드링 처리하여 신호 왜곡 리스크를 사전에 소거해야 합니다.

실시간 디버그 모드 차단 CONFIG 설정 오류

M487의 CONFIG 레지스터 설정에서 보안 침해 방지 잠금(Security Lock) 비트가 켜져 있는 상태라면 디버거의 내부 핵심 코어 제어 회로(SWDC/ETMC)가 강제 물리 차단됩니다. ETM이 켜지지 않는다면 CONFIG0 레지스터 비트 상태를 먼저 확인하여 디버그 기능 개방 상태인지 크로스 체크하십시오.

6. 참고 자료 및 레퍼런스 (References)
