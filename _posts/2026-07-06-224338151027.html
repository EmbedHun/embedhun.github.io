1. 개요 및 배경

임베디드 제품 개발 완료 후 소비자나 현장 유지보수 요원이 분해 없이 새로운 기능 추가나 버그 수정을 위한 펌웨어 업데이트를 수행할 수 있게 하는 ISP(In-System Programming) 및 부트로더(Bootloader) 기능은 현대 마이크로컨트롤러(MCU) 설계에 없어서는 안 될 주요 인프라입니다.

누보톤 N76E003 및 대부분의 NuMicro 계열 MCU들은 내부 플래시(Flash) 메모리를 물리적으로 두 개의 독립된 코드 보관 전용 파티션인 APROM(Application ROM)과 LDROM(Loader ROM)으로 나누어 할당하는 아키텍처를 제공합니다.

많은 주니어 임베디드 개발자들이 이 두 파티션의 차이를 혼동하거나, 펌웨어 다운로드 시 어떤 레지스터와 하드웨어 부팅 설정이 관여하여 부트로더(ISP)에서 메인 앱(APROM)으로 제어권을 이전하는지 그 하드웨어 제어 원리를 정확히 파악하지 못해 업그레이드 실패 장애를 일으킵니다.

이 가이드북은 누보톤의 하드웨어 플래시 제어 규격과 레지스터 스펙을 토대로 APROM/LDROM 분할 배치 구조 및 ISP 통신 기동 시 하드웨어 부팅 제어 흐름을 명확하게 설명합니다.

2. 메모리 파티션 맵 구성 (APROM vs LDROM)

물리적인 단일 내장 플래시 메모리 다이(Die) 안에서 두 영역은 주소 번지에 따라 명확한 용도별 독립 공간으로 분리됩니다.

APROM (Application ROM)

  • 용도: 사용자의 메인 애플리케이션 제어 소프트웨어 코드가 보관되는 메인 스토리지 공간.
  • N76E003 기준 크기: 최대 18KB 대역 (주소 범위: 0x0000 ~ 0x47FF)

LDROM (Loader ROM)

  • 용도: UART, I2C 등 통신 신호를 수신해 APROM 플래시 영역을 지우고 덮어쓰는 ISP 부트로더 소프트웨어가 보관되는 시스템 전용 공간.
  • N76E003 기준 크기: 최대 4KB 대역 (주소 범위: 0x0000 ~ 0x0FFF, 독립된 별도 주소 맵으로 할당)

3. CONFIG 레지스터 설정 및 부트 타겟 제어 (CBS 비트)

전원 인가 직후(Power-on Reset) CPU의 프로그램 카운터(PC) 레지스터가 어느 메모리 영역의 0번지 코드를 가리키고 부팅을 시작할지 결정하는 열쇠는 바로 사용자 구성 비트인 CONFIG0 레지스터의 CBS 비트입니다.

부팅 시작 위치 설정 제어 규격 (CONFIG0의 CBS 비트)

  • CBS = 1 (APROM 부팅): 전원 인가 시 즉시 메인 애플리케이션 코드가 실행됩니다. 일반 양산 제품의 실사용 모드입니다.
  • CBS = 0 (LDROM 부팅): 전원 인가 시 즉시 LDROM의 ISP 부트로더 코드가 실행됩니다. 업데이트 및 공장 출하 초기 펌웨어 다운로드 모드입니다.

4. CHPCON 레지스터 기반 ISP(IAP) 제어 및 소프트웨어 리셋 C 코드

메인 앱(APROM) 실행 도중 특정 UART 패킷(예: 업그레이드 시작 플래그)을 수신하면 하드웨어 리셋 없이 소프트웨어 명령으로 LDROM(부트로더)으로 복귀하는 CHPCON 레지스터 제어 및 소프트웨어 리셋 시퀀스 구현 C 소스코드입니다.

#include "N76E003.h"

void Go_To_LDROM_ISP(void)
{
    // 1. Timed Access(TA) 시퀀스: 보호된 레지스터는 쓰기 직전마다 필요
    TA = 0xAA;
    TA = 0x55;
    // 2. 칩 컨트롤 레지스터(CHPCON) 설정
    // IAP(ISP) 기능 활성화 비트 세팅
    // CHPCON 레지스터의 IAPEN 비트(bit0, IAP Enable)를 켭니다.
    CHPCON |= 0x01;
    // 3. CHPCON 의 BS 비트(bit1)를 1로 설정하여 다음 리셋 시 LDROM에서 부팅하도록 지정 (쓰기마다 TA 시퀀스 필요)
    TA = 0xAA;
    TA = 0x55;
    CHPCON |= 0x02;
    // 4. 소프트웨어 하드웨어 리셋 트리거 발생
    // CHPCON 레지스터의 SWRST 비트를 1로 설정하여 소프트웨어 리셋 발생 (BS 는 유지되므로 LDROM에서 부팅)
    TA = 0xAA;
    TA = 0x55;
    CHPCON |= 0x80;
}

void main(void)
{
    // UART 초기화 및 수신 대기 루프 구동
    while(1)
    {
        // 0xA5 바이트가 UART로 수신되면 ISP 모드(LDROM)로 전환 실행
        if (UART_Receive_Char() == 0xA5)
        {
            Go_To_LDROM_ISP();
        }
    }
}

5. 임베디드 FAE 리스크 분석 및 예방 대책

IAP 오제어로 인한 CONFIG 바이트 오기록 리스크

IAP 로 CONFIG 바이트를 잘못 기록하면 LOCK 비트가 0(칩 잠금)으로 바뀌어, 병렬 라이터나 ICP 로 읽은 플래시 내용이 모두 FFH 로 보이고 CONFIG 바이트를 개별로 지우거나 쓸 수 없게 될 수 있습니다. 칩이 손상되는 것은 아니며, Whole Chip Erase 를 실행하면 잠금이 풀립니다. 다만 이때 플래시 메모리와 CONFIG 의 내용이 모두 지워지므로 펌웨어를 다시 써 넣어야 합니다. 플래시 쓰기 작업 수행 시에는 반드시 VDD 전원을 2.4V~5.5V 범위로 견고히 유지하고, 시스템 클럭 소스 안정화가 끝났음을 알리는 보증 비트(CKSWT 의 HIRCST 등)를 확인한 직후 IAP 제어 명령을 동작시키십시오.

LDROM에서 APROM으로 직접 점프하는 방식의 인터럽트 벡터 리스크

LDROM에서 APROM으로 펌웨어 카피 및 플래시 업로드가 완료된 후, LDROM 코드가 단순 함수 포인터 분기 방식으로 APROM의 0x0000 번지로 강제 점프(Jump)하여 제어권을 이전하면, 인터럽트 벡터 테이블의 오프셋 물리 맵핑 주소가 여전히 LDROM 주소 맵에 고정되어 오작동을 일으킵니다. 반드시 소프트웨어 리셋 명령(SWRST)을 통해 칩 전체가 하드웨어적으로 클린 리셋 상태에서 새로 부팅(이때 CHPCON 의 BS 비트를 0으로 써서 APROM 타겟 부팅)을 시작하도록 부팅 시퀀스를 설계하십시오.
