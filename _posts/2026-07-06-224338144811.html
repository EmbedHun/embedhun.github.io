1. 개요 및 배경

누보톤 N76E003 평가용 보드인 NuTiny-SDK-N76E003-V2.1 보드는 MCU 칩과 디버깅 라이터기인 Nu-Link-Me 장치가 하나의 기판에 통합된 편리한 개발 보드입니다. 이 보드는 PC와 USB 케이블로 연결 시 디버깅뿐만 아니라 가상 COM 포트(Virtual COM Port) 통신을 위한 가상 직렬 드라이버가 윈도우 상에 자동 생성되어 간편한 디버그 메시지 모니터링이 가능합니다.

그러나 수많은 개발자들이 N76E003 UART 테스트 코드를 올바르게 빌드하고 PC의 터미널 프로그램을 해당 포트로 열었음에도 수신 메시지가 전혀 나타나지 않고 송신 문자도 MCU로 들어가지 않는 직렬 통신 먹통 오류에 직면합니다.

이 가이드북은 누보톤 하드웨어 설계 명세를 기반으로 NuTiny 보드 상의 VCOM 라인이 물리적으로 단선되어 통신 불능 상태가 되는 구조적인 원인을 밝히고, 기판을 수정하여 통신 링크를 정상 복구하는 실무 해결책을 제공합니다.

2. 오작동 원인 분석 (물리적 회로 단선 구조)

가장 빈번하게 발생하지 않는 하드웨어 원인은 바로 기판 중간에 위치한 VCOM 점퍼 패드가 오픈(Open)되어 있기 때문입니다.

NuTiny 보드는 생산 출하 시 기본 설정으로 N76E003 MCU의 UART0 포트 핀(TXD_0: P0.6, RXD_0: P0.7)과 디버거 장치인 Nu-Link-Me의 직렬 브리지 회로 연결을 완전히 떼어놓은 단선(NC) 상태로 제작됩니다.

이는 사용자가 해당 포트 핀들을 일반 범용 I/O 핀으로 설계하여 전압이 부딪히는 간섭을 원천 차단하기 위함입니다. 따라서 사용자가 가상 직렬 통신(VCOM) 기능을 활성화하여 모니터링하려면, 기판 상에서 이 물리적인 단선 지점을 납땜 등을 통해 직접 수동으로 도통시켜 주어야 합니다.

3. 하드웨어 수정 단계 (Solder Bridge 납땜 패드 쇼트)

NuTiny-SDK-N76E003-V2.1 보드의 기판 중앙 분리선 부근을 보면, 가상 직렬 연결을 담당하는 미세한 구리 패드 회로가 인쇄되어 있습니다.

복구 절차

  1. 보드의 전원을 컴퓨터에서 완전히 분리합니다.
  2. 기판 중앙 분리 점선(브이컷 라인) 바로 왼쪽에 직사각형 모양으로 분리된 2쌍의 땜납 패드(Solder Bridge 패드)를 찾습니다. 일반적으로 기판 실크 인쇄로 TX, RX 또는 VCOM이라고 표시되어 있습니다.
  3. 인쇄 패턴의 끊겨 있는 패드 쌍 위에 땜납을 살짝 올리고 인하두로 가열하여 두 패드가 전기적으로 연결되도록 쇼트(Short)시킵니다.
  4. 패드가 연결되면 N76E003의 TXD(P0.6) 신호가 Nu-Link-Me 디버거의 직렬 RX 핀으로, RXD(P0.7) 신호가 디버거의 직렬 TX 핀으로 물리적으로 도통하게 됩니다.

4. UART0 펌웨어 초기화 검증 소스코드

N76E003 보드에서 VCOM 도통을 확인하기 위해 115200bps 속도로 문자 데이터를 연속 송신하는 표준 C 코드 템플릿입니다.

#include "N76E003.h"

void UART0_Init_115200(void)
{
    // 1. 다중 기능 핀 설정: P0.6을 UART0 TXD로, P0.7을 UART0 RXD로 할당
    Set_All_GPIO_Quasi_Mode;
    // 2. 타이머 1을 UART0의 보오레이트(Baud Rate) 발생기로 지정
    SCON = 0x50;     // UART0 모드 1 (8비트 데이터, 가변 속도), 수신 인에이블
    TMOD |= 0x20;    // 타이머 1 모드 2 (8비트 자동 재로드 타이머)
    // 3. 115200bps 보오레이트 계산을 위한 레지스터 값 설정 (내장 16MHz HIRC 기준)
    TH1 = 256 - (16000000UL / (16UL * 115200UL));
    TR1 = 1;         // 타이머 1 기동
    TI = 1;          // 첫 번째 전송 트리거용 송신 플래그 인에이블
}

void Send_Char_UART0(uint8_t data)
{
    while (!TI);    // 이전 버퍼 송신 완료 대기
    TI = 0;         // 송신 플래그 클리어
    SBUF = data;    // 직렬 포트 버퍼에 데이터 적재
}

void main(void)
{
    // 시스템 레지스터 잠금 해제 및 UART 설정
    SYS_UnlockReg();
    UART0_Init_115200();
    while(1)
    {
        // PC 화면으로 'U' (0x55) 문자를 100ms마다 송신
        Send_Char_UART0('U');
        Timer0_Delay100ms(1);
    }
}

5. 임베디드 FAE 리스크 분석 및 예방 대책

점퍼 쇼트 후 I/O 핀 멀티플렉싱 충돌 리스크

VCOM 패드를 납땜으로 쇼트시킨 후에는 N76E003의 P0.6 및 P0.7 핀이 Nu-Link-Me 장치의 드라이버 출력 라인과 상시 연결된 상태가 됩니다. 만약 펌웨어 코드 내부에서 실수로 P0.6이나 P0.7 핀의 속성을 강제 푸시풀 출력 모드(Push-pull Output Mode)로 설정하고 전압 신호(Low/High)를 제어하려고 시도하면, 디버거의 직렬 버퍼 IC 출력 회로와 충돌이 발생해 과전류가 흐르고 오작동 및 핀 드라이버 단락 파손이 유발될 수 있습니다. VCOM 연결 후에는 해당 핀들을 절대로 일반 GPIO 제어 용도로 중복 사용하지 마십시오.

컴퓨터 직렬 터미널 버그 및 세션 락 오류

터미널 연결 시 가상 COM 드라이버의 세션이 잠겨 문자 전송이 중간에 멈추는 에러가 발생할 수 있습니다. 수정한 직후에는 포트 접속을 시도하기 전 장치 관리자에서 드라이버를 재설정하거나 터미널 툴(예: Tera Term, Putty 등)의 흐름 제어(Flow Control) 옵션을 하드웨어/소프트웨어 제어 없이 없음(None) 상태로 지정하여 프레임 오류가 없는 통신을 유지하십시오.
