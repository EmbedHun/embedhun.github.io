1. 개요 및 배경

누보톤 N76E003(18KB Flash)과 그 후속작인 MS51 시리즈(8KB, 16KB 또는 32KB Flash)는 초저가형 8비트 마이크로컨트롤러(MCU) 시장에서 널리 쓰이는 베스트셀러 칩셋입니다.

하지만 이를 제어하기 위해 윈도우 환경에서 범용으로 쓰이는 Keil C51 컴파일러의 무료 평가판(Evaluation) 버전은 컴파일 가능한 이진 코드의 크기가 단 2KB로 제한됩니다. 2KB가 넘어가면 정식 라이선스를 구매하지 않는 한 빌드 자체가 불가능해지므로, 칩의 실제 하드웨어 용량을 다 쓰지 못하는 심각한 툴 제약에 직면합니다.

이 문제를 우회하고 윈도우뿐만 아니라 리눅스 및 맥OS 환경에서도 100% 무료로 코드 제한 없이 8051 펌웨어를 빌드하기 위해 해외 글로벌 오픈소스 생태계에서는 SDCC(Small Device C Compiler) 컴파일러와 VS Code 조합을 널리 사용합니다.

이 가이드북은 누보톤의 표준 Keil C51 기반 BSP 소스코드를 오픈소스 컴파일러인 SDCC 규격으로 완벽하게 마이그레이션하기 위한 C 코드 문법 매핑 테이블과 핵심 이식 가이드라인을 제시합니다.

2. Keil C51과 SDCC 컴파일러 문법 변환 규격 (Syntax Mapping)

8051 코어는 내장 레지스터 및 특수 기능 레지스터(SFR), 그리고 다양한 메모리 영역(SRAM, Flash)의 주소를 지칭하는 고유 키워드를 사용합니다. 두 컴파일러 간의 문법 차이를 규격별로 정리한 대조표입니다.

특수 기능 레지스터 (SFR) 정의 방식

  • Keil C51: sfr P0 = 0x80;
  • SDCC: __sfr __at (0x80) P0;

단일 비트 레지스터 (SFR Bit) 정의 방식

  • Keil C51: sbit P05 = P0^5; 또는 sbit P05 = 0x85;
  • SDCC: __sbit __at (0x85) P05;

인터럽트 서비스 루틴 (ISR) 선언 방식

  • Keil C51: void Timer0_ISR(void) interrupt 1
  • SDCC: void Timer0_ISR(void) __interrupt (1)

메모리 영역 키워드 지정 (SRAM 데이터)

  • Keil C51: data (내부 기본 SRAM), xdata (확장 SRAM, N76E003 은 칩 내부 XRAM 768바이트), pdata (페이징 SRAM)
  • SDCC: __data, __xdata, __pdata

상수 테이블 정의 (Flash 저장공간)

  • Keil C51: unsigned char code table[] = { ... };
  • SDCC: __code unsigned char table[] = { ... };

3. BSP 헤더 파일 리팩토링 및 맵핑 기법

누보톤 공식 8051 BSP는 sfr 및 sbit 키워드로 도배된 헤더 파일(N76E003.h 또는 MS51_8K.h·MS51_16K.h·MS51_32K.h)을 제공하므로, SDCC로 이를 그대로 컴파일하면 수백 개의 문법 에러가 뿜어집니다.

이 문제를 해결하기 위해 해외 오픈소스 라이브러리(N76E003-SDCC-BSP)는 누보톤 N76E003 BSP 를 SDCC 용으로 이식하여, 레지스터를 SDCC 문법(__sfr __at, __sbit __at)으로 직접 정의한 헤더를 제공합니다. Keil 과 SDCC 를 한 소스에서 함께 빌드해야 한다면, 컴파일러 매크로(__SDCC)를 감지하여 레지스터 정의를 나누는 공용 헤더를 직접 만들 수도 있습니다.

[Keil 및 SDCC 호환 헤더 파일 설계 구성 예시]

#ifdef __SDCC
// SDCC 컴파일러 전용 레지스터 정의
#define SFR(name, addr) __sfr __at (addr) name
#define SBIT(name, addr) __sbit __at (addr) name
#else
// Keil C51 컴파일러 전용 레지스터 정의
#define SFR(name, addr) sfr name = addr
#define SBIT(name, addr) sbit name = addr
#endif
// 공용 매크로를 활용한 레지스터 지정 예시
SFR(P0, 0x80);
SBIT(P05, 0x85);

4. 실제 구동 코드 변환 비교 (Keil vs SDCC)

LED3(P0.5) 핀의 상태를 토글하는 실제 동작 소스코드를 두 컴파일러 포맷으로 대조한 사례입니다.

A. Keil C51 기준 원본 소스코드

#include "N76E003.h"
#include "Function_Define.h"
#include "Delay.h"

void main(void)
{
    P05_PushPull_Mode;
    while(1)
    {
        P05 = ~P05;
        Timer3_Delay100ms(5);
    }
}

B. SDCC 컴파일러 규격 이식 소스코드

#include "N76E003_SDCC.h" // SDCC 호환용으로 리팩토링한 헤더

void main(void)
{
    // P0.5 를 푸시풀 모드로 설정 (함수가 아니라 매크로이므로 괄호를 붙이지 않음)
    P05_PushPull_Mode;
    while(1)
    {
        P05 = ~P05; // 핀 제어
        Timer3_Delay100ms(5);
    }
}

5. 임베디드 FAE 리스크 분석 및 예방 대책

메모리 모델(Memory Model) 불일치로 인한 오작동

SDCC는 컴파일 시 기본적으로 Small 메모리 모델(내부 직접 주소 지정 SRAM만 사용)을 채택합니다. 8051 아키텍처의 특성상 내부 직접 SRAM(data 영역)은 하위 128바이트에 불과하고(N76E003 의 내부 SRAM 은 총 256바이트이며 상위 128바이트는 간접 주소 지정 영역입니다), 전역 변수나 지역 변수가 조금만 늘어나도 data 영역이 부족해져 변수값 깨짐 현상이 발생합니다.

이를 예방하기 위해 변수가 많아질 경우 SDCC 컴파일 옵션 파라미터에 --model-large를 명시하여 확장 SRAM 영역(__xdata)을 변수 보관 전용 공간으로 활용하도록 빌드 옵션을 조정해야 합니다.

어셈블리 인라인 구문 컴파일 오류

누보톤 공식 BSP 의 TA 보호 레지스터 해제 코드는 TA=0xAA; TA=0x55; 를 쓰는 C 매크로로 작성되어 있어 그대로 이식됩니다. 다만 achilikin 의 SDCC 이식본은 클럭 전환 레지스터처럼 TA 보호가 걸린 곳에서 SDCC 가 추가 명령을 끼워 넣어 보호가 깨지지 않도록 __asm__("orl _CKSWT,#0x20") 형식의 인라인 어셈블리를 사용합니다. Keil 은 #pragma ASM 으로, SDCC 는 __asm__("...") 또는 __asm ~ __endasm 구문으로 어셈블리를 감싸므로, 인라인 어셈블리가 있는 부분은 SDCC 형식으로 바꿔 주어야 정상 빌드가 가능합니다.
