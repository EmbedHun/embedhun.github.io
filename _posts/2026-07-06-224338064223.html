1. 개요 및 배경

NUC980 시리즈는 ARM926EJ-S 코어(최대 300MHz)를 탑재하고, LQFP 패키지 품번은 DDR2 SDRAM 128MB 또는 64MB를 내장합니다(품번에 따라 다름). 누보톤은 NUC980용 임베디드 리눅스(Embedded Linux) BSP를 제공합니다.

이 가이드북은 누보톤의 공식 개발용 Buildroot 환경을 사용해 커널을 빌드하고, Paho MQTT C 라이브러리를 연동하여 보드의 입출력(GPIO, LED) 상태를 실시간 제어하는 IoT 클라이언트 펌웨어 스택 구축의 전체 프로시저를 설명합니다.

2. 하드웨어 환경 및 목표 아키텍처

본 데모의 대상 구성은 다음과 같습니다.

  • 대상 보드: NuMaker-IIoT-NUC980, NuMaker-IIoT-NUC980G2 및 NuMaker-RTU-NUC980 (Chili)
  • 통신 채널: 온보드 이더넷(Ethernet) 포트 및 MQTT 프로토콜 (Broker: test.mosquitto.org)

[시스템 구조 데이터 흐름]

Android IoT MQTT Panel (App) -> MQTT Broker (test.mosquitto.org Port 1883) -> NUC980 Embedded Linux (Ethernet) -> LED3 (GPIO), K1 (Input Switch)

3. Buildroot 및 Linux 커널 환경 구성 (Step-by-Step)

개발 PC에서 임베디드 Linux OS 이미지 컴파일 도구인 Buildroot를 복제하고 패키지를 추가 설정합니다.

1) 소스코드 복제 및 보드 설정 (Target Config)

누보톤 공식 Buildroot 레포지토리를 클론하고 보드 레이아웃에 맞춰 초기 설정을 불러옵니다.

$ git clone https://github.com/OpenNuvoton/buildroot_2024
$ cd buildroot_2024

보드 유형에 맞는 defconfig 구성 선택 (하나만 실행)

  • NuMaker-IIoT-NUC980 보드
$ make nuvoton_nuc980_iot_defconfig
  • NuMaker-IIoT-NUC980G2 보드
$ make nuvoton_nuc980_iot_g2_defconfig
  • NuMaker-RTU-NUC980 (Chili) 보드
$ make nuvoton_nuc980_chili_defconfig

2) Paho MQTT C 클라이언트 라이브러리 활성화

빌드 루트 메뉴 설정을 열어 네트워킹 라이브러리를 추가합니다.

$ make menuconfig
  • 이동 경로: Target packages -> Libraries -> Networking
  • 선택 항목: paho-mqtt-c 활성화

설정을 Save 한 뒤 Exit 합니다.

3) 리눅스 커널 GPIO 및 키보드 입력 인터페이스 활성화

보드 상의 스위치(K1) 입력 이벤트를 리눅스 표준 입력 장치 시스템(/dev/input/event*)으로 읽어오기 위해 커널 드라이버를 활성화합니다.

$ make linux-menuconfig
  • 활성화 필수 드라이버 경로:

Device Drivers -> Input device support -> Event interface (이벤트 장치 인터페이스 생성)

Device Drivers -> Input device support -> Keyboards -> Nuvoton keys support (누보톤 온보드 키 GPIO 인터페이스 연결)

설정을 Save 한 뒤 Exit 합니다.

GitHub - OpenNuvoton/buildroot_2024: Buildroot 2024.02

4) 디바이스 트리(DTS) 상의 I2C 드라이버 스펙 조정

Chili 보드의 경우 기본적으로 I2C 버스가 꺼져 있으므로(i2c1 status = "disabled") 디바이스 트리 소스를 찾아 핀 컨트롤 상태를 활성화해야 합니다. nuc980-iot-v1.0.dts·nuc980-iot-g2-v1.0.dts 의 i2c1 도 status = "disabled" 로 되어 있습니다.

수정 파일: 커널 소스의 arch/arm/boot/dts/nuc980-chili.dts

i2c1: i2c1@b0081000 {
    status = "okay";
    pinctrl-0 = <&pinctrl_i2c1_PB>;
};

5) 시스템 이미지 최종 빌드

설정이 완료되었으면 크로스 컴파일러를 가동하여 타겟 리눅스 커널 및 RootFS를 제작합니다.

$ make

빌드가 완료되면 output/images/ 디렉토리에 커널 이미지(uImage)와 루트 파일 시스템 이미지(Chili: JFFS2, IIoT: UBI)가 생성됩니다.

4. C 기반 MQTT 클라이언트 애플리케이션 작성

빌드된 툴체인 환경의 크로스 컴파일 환경 변수를 로드한 후, Paho 라이브러리를 바인딩하여 MQTT 송수신 어플리케이션(rcdemo.c)을 작성하고 컴파일합니다.

1) 환경 변수 세팅 및 컴파일 명령어

// 1. 크로스 컴파일러 경로 및 환경 변수 자동 바인딩
$ source ./buildroot_2024/output/host/environment-setup
// 2. rcdemo.c 파일 빌드 (정적 링킹으로 libpaho-mqtt3c 내장)
$ $CC rcdemo.c -o rcdemo -Ibuildroot_2024/output/staging/usr/include -Lbuildroot_2024/output/staging/usr/lib -Wl,-Bstatic -lpaho-mqtt3c -Wl,-Bdynamic

2) 핵심 C 소스 코드 구조 및 MQTT 전송 알고리즘

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <pthread.h>
#include <fcntl.h>
#include <linux/input.h>
#include <linux/i2c-dev.h>
#include <sys/ioctl.h>
#include "MQTTClient.h"
#define ADDRESS     "tcp://test.mosquitto.org:1883"
#define CLIENTID    "NUC980_FAE_Client"
#define TOPIC_STATUS  "board/status"
#define TOPIC_TEMP    "board/temperature/1"
#define TOPIC_BUTTON  "board/buttons/1"
#define TOPIC_LED     "board/leds/1"
MQTTClient client;
// MQTT 메시지 수신(Subscribe) 콜백 루틴: LED ON/OFF 제어

int messageArrived(void *context, char *topicName, int topicLen, MQTTClient_message *message) {
    char* payload = (char*)message->payload;
    printf("Message arrived on topic: %s, payload: %.*s\n", topicName, message->payloadlen, (char*)message->payload);
    // LED3(PB8, NuMaker-IIoT-NUC980) 제어: GPIO sysfs 사용 (사전에 echo 40 > /sys/class/gpio/export, echo out > /sys/class/gpio/gpio40/direction 필요)
    if (strcmp(payload, "ON") == 0) {
        system("echo 1 > /sys/class/gpio/gpio40/value"); // PB8 출력 High
    } else {
        system("echo 0 > /sys/class/gpio/gpio40/value"); // PB8 출력 Low
    }
    MQTTClient_freeMessage(&message);
    MQTTClient_free(topicName);
    return 1;
}

int main(int argc, char* argv[]) {
    MQTTClient_connectOptions conn_opts = MQTTClient_connectOptions_initializer;
    int rc;
    // 1. MQTT 클라이언트 인스턴스 생성
    MQTTClient_create(&client, ADDRESS, CLIENTID, MQTTCLIENT_PERSISTENCE_NONE, NULL);
    conn_opts.keepAliveInterval = 20;
    conn_opts.cleansession = 1;
    // 2. 메시지 수신 콜백 함수 등록
    MQTTClient_setCallbacks(client, NULL, NULL, messageArrived, NULL);
    // 3. 브로커 연결 수행
    if ((rc = MQTTClient_connect(client, &conn_opts)) != MQTTCLIENT_SUCCESS) {
        printf("Failed to connect, return code %d\n", rc);
        exit(EXIT_FAILURE);
    }
    // 4. LED 제어 토픽 구독 등록
    MQTTClient_subscribe(client, TOPIC_LED, 1);
    // 5. 최초 연결 시 보드 활성화 상태 알림 (Publish)
    MQTTClient_message pubmsg = MQTTClient_message_initializer;
    pubmsg.payload = "ONLINE";
    pubmsg.payloadlen = 6;
    pubmsg.qos = 1;
    pubmsg.retained = 0;
    MQTTClient_publishMessage(client, TOPIC_STATUS, &pubmsg, NULL);
    printf("MQTT Client is running.\n");
    // 이외 버튼 감지 스레드 및 온도 센서 폴링 루프 가동
    while(1) {
        // 주기적인 센서값 전송 또는 이벤트 대기 루프
        sleep(5);
    }
    MQTTClient_disconnect(client, 10000);
    MQTTClient_destroy(&client);
    return rc;
}

5. 임베디드 FAE 리스크 분석 및 예방 대책

브로커 연결 끊김 처리

MQTTClient_setCallbacks()로 연결 끊김 콜백(MQTTClient_connectionLost)을 등록하면, 클라이언트가 서버와의 연결을 잃었을 때 클라이언트 라이브러리가 이 콜백을 호출합니다. 애플리케이션은 이 콜백에서 재연결 시도나 문제 보고 같은 적절한 조치를 해야 합니다. 위 예제 코드는 이 콜백 자리에 NULL을 넘기고 있습니다.

로그 저장 위치

누보톤 NUC980용 Buildroot 설정(nuvoton_nuc980_iot / iot_g2 / chili defconfig)은 기본 루트 파일 시스템 스켈레톤을 사용하며, 이 스켈레톤에서 /var/log 는 ../tmp 를 가리키는 심볼릭 링크입니다. /tmp 는 IIoT 설정에서는 tmpfs, Chili 설정에서는 ramfs 로 마운트됩니다.
