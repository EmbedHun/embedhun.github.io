1. 개요 및 배경

임베디드 제품의 대량 생산 라인이나 공장 자동 구동 펌웨어 테스트 환경에서는 마우스로 매번 버튼을 눌러야 하는 GUI 프로그램(ICP Tool) 대신, 백그라운드에서 배치 파일이나 명령행 스크립트로 동작하는 CLI(Command Line Interface) 방식의 프로그래밍 유틸리티가 필수적입니다.

누보톤은 이를 지원하기 위해 Nu-Link_Command_Tool.exe 실행 프로그램을 공식 툴 패키지에 포함시켜 제공하고 있습니다.

하지만 생산 라인 세팅 단계에서 가장 빈번하게 발생하는 골칫거리 장애는 바로 "NuLink와 연결된 대상 IC 칩을 찾을 수 없습니다.(Target IC not found!!!)"라는 CLI 연결 실패 에러입니다.

동일한 Nu-Link 프로그래머와 똑같은 보드를 연결한 상태에서 GUI 기반의 NuMicro ICP Programming Tool은 칩을 백발백중으로 올바르게 감지하는데, 오직 커맨드 라인 프로그램만 타겟 칩을 인식하지 못하고 프로그램을 정지해 버립니다.

이 가이드북은 누보톤 프로그래머 내부 통신 라이브러리의 구조적 불일치를 정밀 분석하여, 타겟 인식 에러를 즉각 제거하고 안정적인 양산 자동 굽기 스크립트를 구현하는 해결 가이드를 제안합니다.

2. 문제 발생의 본질적 이유 (디바이스 데이터베이스의 파편화)

GUI ICP Tool 프로그램과 CLI Command Tool은 원래 하나의 드라이버와 동일한 통신 라이브러리(NuLink.dll)를 이용해 칩에 접속하도록 설계되어 있습니다.

하지만 누보톤 공식 홈페이지에서 배포되는 ICP 설치 패키지 버전에 따라, 두 프로그램이 담겨 있는 로컬 폴더 주소와 디바이스 정보 데이터베이스(Device.xml 및 칩셋 설정 정보)가 파편화되어 버전 불일치가 일어나는 버그가 있습니다.

특히 신제품 칩셋(예: NUC121, NUC126, M031 등)이 출시되었을 때 GUI ICP 프로그램 폴더의 데이터베이스는 정상 설치 및 갱신되지만, 별도의 하위 폴더에 보관되는 Command Tool 실행 폴더의 디바이스 맵 리스트는 낡은 버전에 머물러 있어 타겟 코드가 일치하지 않아 감지 단계에서 에러를 출력하고 강제 통신 단절을 일으키는 것입니다.

3. 실무 해결 프로시저 (디바이스 데이터베이스 강제 동기화)

구버전 디바이스 맵을 갱신하여 칩 인식 실패 오류를 즉시 해결하는 물리적 데이터 패칭 조치법입니다.

1. 누보톤 툴 폴더의 설치 경로를 파악합니다. 일반적으로 아래의 두 경로에 각각 툴이 설치되어 있습니다.

- GUI ICP 툴 경로: C:\Program Files (x86)\Nuvoton Tools\NuMicro ICP Programming Tool\

- CLI 커맨드 툴 경로: C:\Program Files (x86)\Nuvoton Tools\Nu-Link Command Tool\ (또는 ICP 폴더 내부의 CmdTool 하위 디렉토리)

2. GUI ICP 툴 폴더 내부에 존재하는 다음의 최신 설정 및 데이터베이스 파일들을 복사(Copy)합니다.

- Device.xml (최신 지원 칩 리스트 맵)

- NuLink.dll (Nu-Link 하드웨어 통신용 다이내믹 링크 라이브러리)

- AP_Config.xml

3. 복사한 파일들을 CLI Command Tool 실행 파일(Nu-Link_Command_Tool.exe)이 위치한 폴더로 가져가서 기존의 파일 위에 강제 붙여넣기(Overwrite)하여 동기화합니다.

이렇게 데이터베이스를 패치해 주면 Command Tool이 GUI 버전과 완벽히 일치하는 디바이스 서치 알고리즘을 사용하게 되므로, 타겟 감지 오류 없이 모든 최신 칩을 CLI 명령으로 정상 인식하기 시작합니다.

4. 배치 파일 기반 자동 다운로드 명령어 구성 가이드

패치가 완료된 상태에서 N76E003 8051 칩의 APROM과 CONFIG를 일괄 자동 포맷팅 및 다운로드하는 실무 양산 배치 스크립트(.bat) 예제입니다.

@echo off

set TOOL_PATH="C:\Program Files (x86)\Nuvoton Tools\Nu-Link Command Tool\Nu-Link_Command_Tool.exe"

echo [1단계] 누보톤 타겟 칩 정보 확인

%TOOL_PATH% -t N76E003 -i

if %errorlevel% neq 0 goto :FAIL

echo [2단계] 타겟 칩 플래시 완전 소거 (Chip Erase)

%TOOL_PATH% -t N76E003 -e chip

if %errorlevel% neq 0 goto :FAIL

echo [3단계] 펌웨어 이진 파일 다운로드 (APROM)

%TOOL_PATH% -t N76E003 -w aprom firmware.hex

if %errorlevel% neq 0 goto :FAIL

echo [4단계] 하드웨어 CONFIG 레지스터 설정

%TOOL_PATH% -t N76E003 -w config 0xff 0xff 0xff 0xff

if %errorlevel% neq 0 goto :FAIL

echo [성공] 펌웨어 다운로드 완료!

pause

exit

:FAIL

echo [에러] 통신 또는 다운로드 과정 중 실패가 발생했습니다!

pause

exit

5. 임베디드 FAE 리스크 분석 및 예방 대책

펌웨어 버전 및 하드웨어 Nu-Link ID 매칭 오류

여러 대의 Nu-Link 프로그래머를 단일 PC에 주렁주렁 연결하여 다중 굽기(Multi-programming) 자동화 환경을 구축하는 경우, 개별 Nu-Link의 펌웨어 내부 버전이 다르면 CLI 실행 시 특정 포트의 ID를 잡지 못하고 락이 걸립니다. 배치 프로그램 구동 전 반드시 ICP GUI 툴의 '도구' -> '펌웨어 업데이트' 메뉴를 통해 물리적 연결된 모든 Nu-Link의 내부 펌웨어 버전을 동일한 최신 버전으로 싹 일치시켜 주어야 CLI 파라미터 제어 시 식별 인덱스 충돌을 예방할 수 있습니다.

CLI 스크립트 내 디바이스 이름 대소문자 검증 실패

Command Tool은 명령 인자 중 타겟 칩 이름 지정 플래그(-t)의 대소문자를 극도로 엄격하게 구별합니다. 예를 들어 n76e003(소문자) 또는 N76e003으로 적으면 XML 맵 매칭 실패로 인식 불능 오류가 나므로, 반드시 최신 Device.xml에 적힌 대문자 형태인 N76E003 또는 M031G으로 철자를 한 토막도 빠짐없이 대조하여 명시해야 합니다.
