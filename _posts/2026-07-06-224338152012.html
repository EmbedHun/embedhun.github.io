1. 개요 및 배경

대용량 파일이나 이미지 데이터를 외부 SPI 플래시 메모리(예: Winbond W25Q32 등)에 실시간으로 기록할 때, 누보톤 M487 MCU가 지원하는 주변장치 직접 메모리 접근(PDMA) 기능은 CPU 점유율을 비약적으로 낮춰주는 핵심 솔루션입니다.

CPU 루프 없이 버퍼에서 SPI FIFO 하드웨어까지 데이터 전송을 완벽히 비동기로 처리할 수 있기 때문입니다.

하지만 현업 개발 과정에서 다수의 엔지니어들이 겪는 치명적인 버그 중 하나는 바로 데이터 누락 및 파일 깨짐 현상입니다.

특히 연속적인 페이지 쓰기(Page Program) 작업을 연달아 수행할 때, 데이터가 군데군데 기록되지 않고 생략되는 오류가 자주 관찰됩니다.

이 문제의 본질은 PDMA 전송 완료 이벤트와 외부 플래시 메모리 칩 내부의 물리적인 쓰기 완료 주기(Write Cycle) 타이밍의 불일치에 있습니다.

이 가이드북은 누보톤 M487 표준 BSP를 기반으로, 외부 플래시 메모리의 BUSY 상태를 효율적으로 체크하여 통신 안전성을 보증하는 최적의 동기화 펌웨어 설계 방식을 분석하고 해결책을 제시합니다.

2. 오작동 원인 분석 (DMA 완료와 물리 쓰기 주기의 불일치)

SPI PDMA 송신 채널은 타겟 버퍼의 모든 데이터를 SPI 컨트롤러의 송신 FIFO 레지스터에 밀어 넣은 즉시 완료(Interrupt) 상태로 천이합니다.

그러나 이 시점에 외부 Winbond 플래시 칩 내부에서는 메모리 셀(Cell)에 전하를 채우는 물리적인 페이지 쓰기 동작이 비로소 시작되며, 이 작업이 완료되기까지는 하드웨어적으로 최대 3ms(밀리초)의 대기 시간이 추가 소요됩니다.

이 물리 동작 시간 동안 플래시 메모리 칩은 외부의 모든 읽기/쓰기 명령을 무시하는 완전 바쁜 상태(BUSY)가 됩니다.

개발자가 PDMA 전송 완료 인터럽트만을 근거로 삼아, 외부 칩 상태를 체크하지 않고 즉시 칩 선택(CS, Chip Select) 신호 핀을 해제하거나 이어서 새로운 쓰기 패킷을 송신하면, 플래시 메모리는 후속 명령을 완전히 드랍하여 데이터 누락 오류가 발생하는 것입니다.

3. 실무 해결책 (상태 레지스터 WIP 비트 폴링 구현)

이 문제를 안전하게 예방하기 위해, PDMA 데이터 전송이 완료된 직후 및 후속 명령을 쓰기 전에 외부 플래시의 상태 레지스터 1(Status Register 1)을 읽어 WIP(Write In Progress, 쓰기 진행 중) 비트가 완전히 해제(0)되었는지 실시간 폴링 검사하는 펌웨어 제어 시퀀스를 추가해야 합니다.

W25Q32 플래시 메모리 제어 바이트 규격

- Read Status Register 1 커맨드 바이트: 0x05

- WIP(Write In Progress) 비트: 상태 레지스터의 최하위 비트(Bit 0). 이 비트가 1이면 칩이 바쁨(BUSY), 0이면 작업 완료(Ready) 상태입니다.

[상태 레지스터 폴링 제어 C 소스코드]

#include "NuMicro.h"

// SPI0 및 PDMA 전송 제어 전역 변수

volatile uint32_t g_u32TxDone = 0;

void PDMA_IRQHandler(void)

{

uint32_t status = PDMA_GET_INT_STATUS(PDMA);

if(status & PDMA_INTSTS_TDIF0_Msk) // 채널 0 (SPI0 TX) 완료 확인

{

PDMA_CLR_CH_INT_FLAG(PDMA, 0, PDMA_CH_INT_FLAG_TD);

g_u32TxDone = 1;

}

}

// 외부 플래시 W25Q32의 WIP(Busy) 비트 해제 대기 함수

void SPI_Flash_Wait_WIP_Clear(void)

{

uint8_t u8Status = 0;

// 1. SPI0 칩 선택 핀 활성화 (Low)

SPI_SET_SS_LOW(SPI0);

// 2. Read Status Register 1 명령(0x05) 송신

SPI_WRITE_TX(SPI0, 0x05);

while(SPI_IS_BUSY(SPI0)); // SPI 통신 완료 대기

SPI_READ_RX(SPI0); // 버퍼 비우기

// 3. WIP 비트가 0이 될 때까지 상태 레지스터 바이트 연속 수신 폴링

do

{

SPI_WRITE_TX(SPI0, 0x00); // 클럭 공급용 더미 데이터 송신

while(SPI_IS_BUSY(SPI0));

u8Status = SPI_READ_RX(SPI0); // 상태 바이트 읽기

} while(u8Status & 0x01); // 최하위 비트(WIP)가 1인 동안 루프 돌며 대기

// 4. SPI0 칩 선택 핀 비활성화 (High)

SPI_SET_SS_HIGH(SPI0);

}

// PDMA 기반 페이지 쓰기 기동 함수

void SPI_Flash_Page_Write_PDMA(uint32_t addr, uint32_t size, uint32_t srcAddr)

{

g_u32TxDone = 0;

// [이전 쓰기 작업이 아직 진행 중인지 먼저 확인]

SPI_Flash_Wait_WIP_Clear();

// 쓰기 허용 명령(Write Enable: 0x06) 실행

SPI_SET_SS_LOW(SPI0);

SPI_WRITE_TX(SPI0, 0x06);

while(SPI_IS_BUSY(SPI0));

SPI_READ_RX(SPI0);

SPI_SET_SS_HIGH(SPI0);

// Page Program 커맨드 및 주소 프레임 전송

SPI_SET_SS_LOW(SPI0);

SPI_WRITE_TX(SPI0, 0x02); // Page Program 명령

SPI_WRITE_TX(SPI0, (addr >> 16) & 0xFF);

SPI_WRITE_TX(SPI0, (addr >> 8) & 0xFF);

SPI_WRITE_TX(SPI0, addr & 0xFF);

while(SPI_IS_BUSY(SPI0));

// PDMA 채널 0 활성화하여 256바이트 데이터 전송

PDMA_SetTransferAddr(PDMA, 0, srcAddr, PDMA_SAR_INC, (uint32_t)&SPI0->TX, PDMA_DAR_FIX);

PDMA_SetTransferCnt(PDMA, 0, PDMA_WIDTH_8, 256);

SPI_TRIGGER_TX_PDMA(SPI0);

// PDMA 전송 완료 인터럽트 대기

while(g_u32TxDone == 0);

// SPI FIFO 비워질 때까지 최종 완료 대기

while(SPI_IS_BUSY(SPI0));

// SPI PDMA 비활성화 및 CS 해제

SPI_DISABLE_TX_PDMA(SPI0);

SPI_SET_SS_HIGH(SPI0);

// [현재 페이지 쓰기 작업이 플래시 칩 내부에서 끝날 때까지 대기]

SPI_Flash_Wait_WIP_Clear();

}

4. 임베디드 FAE 리스크 분석 및 예방 대책

인터럽트 폴링 루프 내 Watchdog Timer 리셋 예외

대용량 데이터를 연달아 기록하는 과정에서 WIP 폴링 대기 루프가 수십 ms 이상 지속적으로 맞물려 실행되면, 시스템 감시 하드웨어인 워치독 타이머(Watchdog Timer)의 킥(Kick) 카운팅 윈도우 한계를 초과하여 CPU 강제 리셋이 유발될 수 있습니다. 대용량 루프 제어 시에는 WIP 폴링 루프 내부 혹은 쓰기 블록 단위 사이에 반드시 워치독 타이머 리셋 매크로 함수(WDT_RESET())를 가미하여 예기치 않은 시스템 하드 리셋 리스크를 차단하십시오.

CS 핀 수동 제어 타이밍 신호 스큐

누보톤 SPI 모듈의 자동 CS 제어(Auto SS) 기능을 활성화하고 PDMA를 가동하면, 데이터 한 단어가 날아갈 때마다 CS 신호가 매번 High로 출렁이며 연속 전송 프레임 구조가 완전히 손상됩니다. 외부 플래시 제어 시에는 반드시 SPI_DisableAutoSS 매크로를 호출해 자동 제어를 끄고, CS 핀(SS) 제어를 전적으로 펌웨어 코드의 GPIO Low/High 레벨 명령을 통해 완벽한 독립된 전송 윈도우 타이밍을 확보하십시오.

5. 참고 자료 및 레퍼런스 (References)

본 기술 가이드는 Winbond W25Q 시리즈 직렬 플래시의 물리적 상태 레지스터 비트 사양서 명세서와 누보톤 M480 시리즈 기술 레퍼런스 매뉴얼(TRM)의 SPI 컨트롤러 및 PDMA 전송 장 절을 기반으로 작성되었습니다. 또한 대용량 데이터 기록 시 발생하는 펌웨어 타임아웃 오류 보고서 및 FAE의 양산 단계 신뢰성 검증 이력 자료를 대조하여 작성된 기술 문서입니다.
